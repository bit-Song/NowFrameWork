# 26 · 阶段总结与下一步

> 更新：2026-11-17。代码基线：`2c30b9e`，已推送至 `origin/main`。本阶段完成 UI 基础流程，完整 UI 框架仍需继续建设。

目前已经可以从 Boot 启动资源服务，加载并显示真实 UI Prefab，再执行隐藏、恢复、关闭和资源释放。下一步优先完善多窗口之间的行为，包括模态遮罩、返回处理和页面导航。

## 1 已完成

### 1.1 已有框架能力

| 模块 | 当前能力 |
|---|---|
| 基础内核 | 模块注册与依赖排序、启动与关闭、日志、事件、时间与计时器、对象池 |
| 资源加载 | 通过 `IAssetService` 获取资源，以 `AssetLease` 管理引用和释放，Addressables 提供实际加载实现 |
| 资源键工具 | 扫描 Addressables Group 中的资源，按目录层级和文件后缀生成 `AssetsKeys`；生成前检查冲突并提示位置 |
| 资源与代码更新 | 已有目录准备、下载、加载和失败处理流程；Windows 资源更新与可选 HybridCLR 链路已有阶段验证 |
| 配置、场景与设置 | 配置加载、场景加载与卸载、小型设置保存、备份恢复与迁移 |
| Boot | 组织启动、项目入口、取消、失败清理与停止流程 |
| 业务程序集 | 统一使用 `Game` 业务程序集，加载示例已迁入，业务脚本可引用生成的资源键 |

这些是当前可用的基础能力，各平台和异常路径的验收范围见 [15 进度与下一步](15-进度与下一步.md)。用户已反馈此前资源加载与基础 API 测试未发现问题。

### 1.2 本阶段新增的 UI 能力

| 能力 | 已实现的行为 |
|---|---|
| 面板会话 | `OpenAsync` 打开面板，`HideAsync` 保留实例并隐藏，`ShowAsync` 恢复显示，`CloseAsync` 结束会话并释放资源 |
| 显隐并发 | 同方向的在途请求合并；动画过程中请求反向时，取消并等待旧过渡退出，再由新过渡接管 |
| 默认动画 | 提供立即切换和 `CanvasGroup` 淡入淡出；淡入淡出使用非缩放时间，从当前透明度继续 |
| 生命周期 | 提供创建、打开、开始显示、显示完成、开始隐藏、隐藏完成、关闭和释放回调 |
| 取消管理 | `SessionToken` 管理会话期间的工作，`VisibleToken` 管理显示期间的工作 |
| 真实资源工厂 | 获取 Prefab 租约、创建实例、设置层级；关闭时确认实例真正销毁后再归还租约 |
| 清理失败恢复 | 销毁等待超时或清理失败时保留资源与记录，允许所有者重试清理 |
| 根节点与适配 | `UiRoot` 管理 Canvas、SafeArea、Page / Popup / Toast 层和显式提供的 EventSystem |
| 模块与启动整合 | `UiModule` 接入项目 Scope，Boot 进入项目后启动 UI，退出时等待 UI 清理 |
| 样例与工具 | 提供最小 Prefab、创建菜单、测试场景和可直接调用的示例脚本 |

UI 包通过 `IAssetService` 获取资源，实际 Addressables 加载由适配包负责。当前可以用它制作普通面板；窗口之间的导航、模态和返回规则需要后续实现。

## 2 验证结果

| 验证 | 结果与范围 |
|---|---|
| 独立消费工程 EditMode | **330 / 330 通过**，0 失败、0 跳过；其中 UI 35 项、销毁等待工具 3 项、资源键生成器 13 项，其余已有模块与 Boot 279 项 |
| Windows x64 Mono Player | 使用真实 Addressables 与 UI 工厂连续执行 **100 次 Open / Close**，结束时 `SessionCount=0`、`ActiveLeases=0` |
| 失败与重试 | 验证销毁超时保留租约、重试后释放，以及 Boot 正常停止和 UI 启动失败回滚 |
| 画面 | 通过相机离屏渲染检查面板背景和文字，截图已归档 |

本轮 UI Player 验证使用 Windows Mono。UI 的 IL2CPP、Android / iOS 和主工程场景的按钮交互仍需单独验证；此前其他模块的 IL2CPP 结果不能替代 UI 的平台验收。

原始报告、截图与验证源代码见 [本阶段证据归档](../evidence/2026-11-17-ui-integration/README.md)。

## 3 在 Unity 中继续测试

1. 打开 [UIIntegration.scene](../../Scenes/UIIntegration.scene)。
2. 将 Addressables 的 Play Mode Script 设为 **Use Asset Database (fastest)**。
3. 点击 Play，等待 Boot 完成，面板会自动加载并显示。
4. 使用底部的 Open / Hide / Show / Close / Reverse / 100 Open/Close 按钮检查流程。Close 后再次显示需要先 Open。
5. 点击 Boot 顶部的“取消 / 停止”，等待清理完成后结束 Play。

调用代码见 [UiFlowSample.cs](../../Game/UiFlowSample.cs)，接口用法、生命周期约定与退出顺序见 [25 UI 最小流程与接入](../04-测试与接入/25-UI最小流程与接入.md)。

## 5 下一步

以下是建议的增量顺序，当前仅记录计划。

| 顺序 | 工作 | 完成标准 |
|---|---|---|
| 1 | 手动确认当前 UI 场景 | 按钮可用，反向切换无闪烁或状态错乱，100 次结束后计数归零，Boot 停止能够完成 |
| 2 | 多窗口顺序与模态遮罩 | 同时打开普通页面和两个弹窗；顶层弹窗接收输入，遮罩阻挡下层；关闭顶层后下层输入恢复 |
| 3 | 返回处理、导航与焦点恢复 | 返回键先交给顶层可返回窗口；返回上一页时状态一致；关闭弹窗后焦点回到仍有效的控件 |
| 4 | DOTween 适配 | 沿用当前取消与反向规则；过渡取消后旧 Tween 停止写入，关闭流程能够等待动画收尾 |
| 5 | 面板缓存与清理 | 明确 Hide、Close 与缓存的关系，验证复用、淘汰和清理后资源计数符合策略 |
| 6 | 平台与正式样例 | 增加 UI 的 Windows IL2CPP 和移动端验证，检查触控、SafeArea、横竖屏及后台恢复 |

下一轮实现建议从第 2 项开始，先建立“页面 + 两层弹窗”的验证场景，再补齐对应自动化用例。缓存放在窗口生命周期和交互规则稳定之后。
