# 06 工程规范、测试与验收

> 上游：[05-技术方案-Addressables与HybridCLR](05-技术方案-Addressables与HybridCLR.md) ｜ 相关：[07-架构决策记录ADR](07-架构决策记录ADR.md)

## 1. 目录规范

```
Assets/_Project/{Scenes,Launcher,HotUpdate,Entry.Console,Settings,Art,Resources}
Assets/_ThirdParty/
Assets/_Raw/
Packages/com.now.nowframework/{Runtime,Editor,Tests,Samples~,Documentation~}
Tools/           构建、CI、表格导出脚本
docs/            本设计文档
```

规则：

- 下划线目录固定排在最前；Unity 自动生成目录（`Library`、`Temp`、`Logs`、`obj`）不得提交。
- `Assets/Resources/` 只允许两个东西：Boot 场景、兜底热更 dll。其他任何资源禁止放入。
- 框架包内不得出现项目名、项目路径、项目特有资源名。
- `_Raw/` 放原始表格与源美术，不进包、可走 LFS。

> **当前偏差（v0.3 校核，2026-11-11）**：以下与本节规范不一致，属"待还的技术债"——
> 1. 设计文档仍在 `Assets/docs/`，应迁到仓库根（或工程根）`docs/`，不要留在 `Assets/` 下，迁移时删掉那 12 个 `.meta`；
> 2. `Packages/manifest.json` 里仍有 `cn.tuanjie.codely.bridge` 与 `file:../.codely-cli/...`：后者是本机路径，且 `.codely-cli/` 已被忽略，换机或 CI 会解析失败，提交前必须移除。
>
> 已还清（2026-11-11）：git 仓库、`.gitignore`（放在 Unity 工程根）、`.gitattributes`（LFS）均已就位。

## 2. 程序集与引用规范

1. 所有 asmdef 关闭 `Auto Referenced`；引用必须显式声明。
2. 引用方向必须符合 [02 第 2 节](02-架构分层与依赖规则.md) 的矩阵；越界由 T01 检查并在 CI 拦截。
3. 不新增程序集，除非满足：独立第三方代码、需要单独裁剪、编译时间收益 > 依赖管理成本。
4. AOT 程序集禁止引用热更程序集；热更程序集禁止引用 Editor 程序集。
5. 平台差异一律走 `IPlatform`，禁止在业务层写 `#if UNITY_STANDALONE`（框架层实现内允许）。
6. 引擎差异只允许出现在构建脚本、`IPlatform` 实现与条件编译常量中；框架层禁止引用团结独有包（`cn.tuanjie.*`）。这不是为双引擎兼容，而是为将来迁移冻结成本（ADR-017）。

## 3. 代码规范

### 3.1 格式

- C# 11（Unity 2022.3 支持范围），4 空格缩进，Allman 大括号。
- 文件名单数、与主类型同名；一个文件一个 public 类型。
- `using` 排序并去重；禁止 `region`。
- 行宽不做硬限制，但单行超过 160 字符需换行。

### 3.2 命名

| 元素 | 规则 | 示例 |
|---|---|---|
| 类型 / 方法 / 属性 / 事件 | PascalCase | `AssetService`、`LoadAsync`、`Opened` |
| 接口 | `I` + PascalCase | `IAssetService` |
| 私有字段 | `_camelCase` | `_refCount` |
| Inspector 序列化字段 | `m_CamelCase` + `[SerializeField] private` | `m_MaxConcurrent` |
| 常量 | PascalCase | `MaxRetry` |
| 事件类（struct） | 过去式 + `Event` | `SceneLoadedEvent` |
| 异步方法 | `Async` 后缀 | `LoadAsync` |
| 布尔 | `Is/Has/Can` 前缀 | `IsValid` |

### 3.3 硬性禁止（Code Review 必查）

| 禁止 | 原因 | 替代 |
|---|---|---|
| `async void` | 异常无法捕获 | `UniTaskVoid` 或 `Forget()` |
| `Task` / `Thread` 直接使用 | 与 UniTask 冲突、线程安全 | `UniTask` + `UniTask.RunOnThreadPool` |
| `Resources.Load` | 破坏包体治理 | `AssetRef` + `IAssetService` |
| `GameObject.Find*` / `FindObjectOfType` | 性能与耦合 | 注入或容器查询 |
| `SendMessage` | 反射、不可搜索 | 事件或接口 |
| 业务代码出现 `Addressables.` | 违反封装 | `IAssetService` |
| 业务代码 `new` 框架内部类 | 违反依赖规则 | 接口 + 容器 |
| 热路径 LINQ / 闭包 / 字符串拼接 | GC | 预分配、缓存、`StringBuilder` |
| 静态可变状态 | 多局游戏残留 | `IAppModule` 实例 |
| `catch (Exception) { }` 空吞 | 掩盖故障 | 记录 + 明确降级 |
| 框架层引用 `Physics` / `Physics2D` / `Rigidbody` / `Collider` | 框架必须维度中立（ADR-021），2D 项目接不进来 | 物理查询由 Gameplay 提供 2D/3D 各自实现 |
| 框架层引用 `Renderer` / `SpriteRenderer` / `Light` / 任何渲染管线命名空间 | 同上，且违反 ADR-016 | 渲染相关只出现在 Gameplay 或接入方项目 |
| Foundation 里出现"相机"概念 | 相机属于 Gameplay（G04） | 相机服务放 Gameplay，Foundation 只管资源/流程/UI |

### 3.4 异常规范

- 可预期失败（资源不存在、网络失败、存档损坏）用返回值或 `TryXxx`；
- 编程错误（参数非法、状态非法、依赖缺失）抛异常；
- 框架边界（模块初始化、异步入口）必须捕获并记录，不得让异常穿到 Unity 主循环；
- 禁止空 catch；每个 catch 必须记录或转换。

## 4. 资源命名

| 类型 | 前缀 | 示例 |
|---|---|---|
| 场景 | `SC_` | `SC_Boot.unity` |
| 界面 Prefab | `UI_` | `UI_MainMenu.prefab` |
| 普通 Prefab | `P_` | `P_Player.prefab` |
| 材质 | `M_` | `M_Default.mat` |
| 贴图 | `T_` | `T_Noise.png` |
| 音频 | `A_` | `A_BGM_Main.ogg` |
| 配置源表 | `CFG_` | `CFG_Item.xlsx` |
| 图集 | `SPR_` | `SPR_UI_Main.spriteatlas` |

- 不使用空格与中文；地址与文件路径均全英文。
- 改名前必须确认是否已被地址引用（T01 提供检查）。
- 变体资源统一后缀 `_Low/_High`，通过 Addressables Variant 管理。

## 5. Git 规范

### 5.1 分支

| 分支 | 用途 |
|---|---|
| `main` | 可发布，永远可出包 |
| `develop` | 日常集成 |
| `feature/<模块>-<简述>` | 功能（关联模块编号，如 `feature/f01-asset-service`） |
| `hotfix/<版本>` | 线上补丁 |

### 5.2 提交

- Conventional Commits：`feat(f01): 资源句柄引用计数`
- 一个提交只做一件事；格式化与逻辑修改分开。
- `.meta` 必须与资源同一次提交；不允许只提交资源不提交 meta。
- 不提交 `Library/`、`Temp/`、`Logs/`、`obj/`、`Build/`、本地产物；也不提交 `.codely-cli/`、`.codelyignore`、`*.csproj`、`*.sln`（AI 工具与 IDE 生成，换机重建）。
- `manifest.json` 里不允许出现 `file:../.codely-cli/...` 这类本机路径依赖——换机与 CI 必炸。
- HybridCLR 的安装数据与生成物都落在 `Library/HybridCLR/`（9.1.0 起；8.x 及更早是工程根的 `HybridCLRData/`），已被 `Library/` 规则整体忽略，不需要额外规则。**代价是删掉 `Library` 就要重跑 `HybridCLR/Installer`**（约 0.8 GB，gitee 拉取）；`ProjectSettings/HybridCLRSettings.asset` 才需要入库。

### 5.3 LFS

`*.psd`、`*.fbx`、`*.wav`、`*.mp4`、`*.tga`、`*.exr` 走 LFS；`Assets` 下的常规 PNG 若 < 1MB 可不用。

### 5.4 版本

`v<主>.<次>.<修订>`；框架版本与项目版本分离：框架打 tag `nowframework/0.1.0`，项目打 `game/0.1.0`。

## 6. 测试策略

### 6.1 金字塔

| 层级 | 范围 | 工具 | 占比 | 执行时机 |
|---|---|---|---|---|
| 单元（EditMode） | 纯逻辑、容器、事件、池、存档迁移、配置校验 | Unity Test Framework | 70% | 每次 PR |
| 集成（PlayMode） | 启动流程、资源加载释放、UI 栈、场景切换 | Unity Test Framework | 20% | 每次 PR / 夜间 |
| 冒烟（构建产物） | 出包 → 启动 → 截图/日志断言 → 退出 | 命令行 + 启动参数 | 10% | 夜间 / 发布前 |

### 6.2 覆盖率目标

| 层 | 行覆盖 | 说明 |
|---|---|---|
| Core | ≥ 80% | 纯 C#，无理由不测 |
| Foundation | ≥ 60% | 依赖 Unity 的部分用假 Provider 覆盖 |
| Gameplay | 不做硬性要求 | 由垂直切片验证 |

不使用覆盖率作为唯一指标：**关键路径必须有用例**，覆盖率高但关键路径无断言视为未完成。

### 6.3 关键用例清单

**C01 容器**

- 依赖顺序初始化；缺失依赖报错含 Id 与链路；循环依赖报错；重复注册报错；关闭严格逆序；单模块异常不吞其他模块错误。

**C04 事件**

- 订阅/退订/发布；优先级顺序；派发中订阅与退订不抛异常；单 handler 异常不影响其余；延迟派发在帧末按序执行；10k 订阅派发 0 GC。

**C05 时间 / C06 池**

- 暂停不影响 unscaled；Delay/Interval 误差 ≤ 1 帧；池复用、上限淘汰、预热、重复释放报错。

**C09 存档**

- 写读一致；v1→v2 迁移；文件截断后可恢复备份；并发写串行化。

**C10 配置**

- 加载与查询；重复 ID 报错；越界报错；热重载触发 `Reloaded`。

**F01 资源**

- 加载/释放；同址并发共享句柄；引用计数归零才真正释放；取消后计数归零；IO 错误重试两次后抛出；泄漏快照能列出未释放地址。

**F03 流程 / F04 UI**

- 流程切换串行；并发切换后者等待；场景卸载后资源归零；UI 开关 100 次无泄漏；返回键按栈消费；缓存池超上限销毁。

**T02 构建**

- 一条命令产出完整产物；补丁可加载；回滚可启动；删远端补丁回退兜底 dll。

### 6.4 测试书写约定

- 测试命名：`MethodName_Scenario_Expected`；
- 一个测试一个断言主题；
- 不使用 `Thread.Sleep`，用 `UniTask.Delay` + 可注入时钟；
- PlayMode 测试必须自行清理场景与句柄，否则后续用例被污染；
- 涉及文件的测试使用临时目录，结束删除。

## 7. CI

| 阶段 | 触发 | 内容 | 时长上限 | 失败处理 |
|---|---|---|---|---|
| PR 检查 | 每次推送 | 编译（batchmode，团结为主）、程序集越界检查、EditMode 单测、0 警告 | 10 min | 阻塞合并 |
| 夜间 | 每日 | PlayMode 单测、Win64 IL2CPP 构建、启动冒烟、性能基准对比、Addressables 构建报告 | 60 min | 通知 + 记录 |
| 发布 | 手动/标签 | 全平台构建、补丁包、归档、版本清单 | 120 min | 阻塞发布 |

CI 命令统一走 `Tools/ci.ps1`，参数：`-Stage {pr|nightly|release}`、`-Platform Win64`、`-EnginePath`（指向 `Tuanjie.exe` 或 `Unity.exe`，不写死）。

冒烟断言最小集：

1. 进程启动 10 秒内退出码 0；
2. 日志出现 `Boot.Completed`；
3. 日志无 `Exception` / `Error`（白名单除外）；
4. 截图与基线差异 < 阈值（可选，M6）。

## 9. 接入指南（新工程，目标 1 人日）

> 依赖版本、git 安装方式与安装顺序见 [08-依赖与资源清单](08-依赖与资源清单.md)。

1. 用**团结引擎 1.8.2**（`2022.3.62t4`）新建工程（URP 模板可选，框架不依赖管线）；
2. `Packages/manifest.json` 增加 `"com.now.nowframework": "file:../com.now.nowframework"`（框架是独立仓库，放在工程同级目录，见 [02 §4](02-架构分层与依赖规则.md)）；
3. 安装 Addressables、HybridCLR（git URL）、UniTask、Input System；
4. 按 [05 第 4 节](05-技术方案-Addressables与HybridCLR.md) 配置 Player Settings；
5. 导入 `SC_Boot` 场景并设为首个场景；`Game.Launcher` 已在场景上；
6. 建第一个 `UIView` 子类，Prefab 放入 `UI/` 组，登记地址 `UI/FirstScreen`；
7. 运行，应看到 Loading → 首屏；日志出现 `Boot.Completed`；
8. 打一次 Win64 IL2CPP 包，验证同一流程；打一次补丁，验证热更生效。
9. **2D 项目接入验证（半天）**：用团结 `Universal 2D` 模板新建空工程，重复第 1–7 步——渲染与物理**不需要动框架**，能见到首屏即通过。这是"框架对 2D 可用"的唯一证据，比写在文档里的承诺可靠。
