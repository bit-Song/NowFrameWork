# NowFrameWork · Unity 通用框架设计与路线图

> 状态：草案 v0.3 ｜ 日期：2026-11-11 ｜ 引擎基线：**团结引擎 1.8.2（2022.3.62t4）单环境**
> 技术栈：Addressables + UGUI + HybridCLR ｜ 目标平台：PC 单机优先（主机为条件项；立项即整体迁移到 Unity，见 ADR-017）

## 1. 这是什么

一套面向中大型单机项目（PC 优先、主机后置）的通用 Unity 框架，代号 **NowFrameWork**。以 UPM 本地包形态交付，分为 Core / Foundation / Gameplay 三层，业务代码独立为热更层；配套构建、热更、测试与工具链规范。

**命名对照**

| 项 | 名称 |
|---|---|
| 产品代号 | NowFrameWork |
| UPM 包 | `com.now.nowframework`（`Packages/com.now.nowframework`） |
| 框架程序集 / 命名空间 | `NowFrameWork.Core` / `.Foundation` / `.Gameplay` / `.Editor` |
| 业务程序集（示例项目） | `Game.Launcher` / `Game.Logic` / `Game.UI` / `Game.Data` |

本目录是**实现前冻结的设计**，不是 API 手册。目标只有一个：另一名工程师读完即可直接进入 M0，不需要再做架构决策。

## 2. 一页速览

| 项 | 结论 |
|---|---|
| 模块规模 | 4 层 / 39 个模块（18 个 P0） |
| 引擎 | **团结引擎 1.8.2（2022.3.62t4）单环境**；只用 2022.3 LTS 公共 API、不引 `cn.tuanjie.*` 包，为将来迁移冻结成本（ADR-017） |
| 交付形态 | UPM 本地包 `com.now.nowframework`，业务工程零复制 |
| 交付边界 | **框架本体 = Core + Foundation + Tooling**（18 个 P0 全在这里）；Gameplay 只交付接口 + `Samples~` 参考实现，2D/3D 由接入方项目各自实现（ADR-021） |
| 资源 | Addressables 作底座，业务只接触 `AssetRef<T>` / `AssetHandle<T>` |
| 热更 | PC：C# dll 热更（HybridCLR 产物经 Addressables 分发）；主机：整包补丁，同一份业务代码双模式编译 |
| UI | UGUI + 轻量 MVP，不引第三方绑定库 |
| 配置表 | 自研 Excel/CSV → 二进制 + 强类型生成，`IConfigSource` 可插拔 |
| 最大技术风险 | Addressables × HybridCLR × IL2CPP 裁剪 → **M0 专项验证**，失败即换 YooAsset |
| 工期估算 | **框架本体 71–92 人日**（M0–M4，单人约 3.5–4.5 个月）；含 Gameplay 示例合计 90–125 人日（单人 5–7 个月）。不含业务内容、美术与主机迁移 |

## 7. 阅读顺序

1. 先读 01，确认范围与预算是否符合项目预期；
2. 再读 02、03，理解分层与模块边界；
3. 排期看 04；
4. 动手前必读 05（资源与热更的所有坑都在这里）；
5. 开始写代码前读 06；出现架构争议时查 07；
6. 开工前按 08 备齐依赖与资源；
7. 实现某个模块前，先看 09 是否有对应章节。

## 9. 下一步

M0 的第一件事不是写框架，而是**把最危险的链路打通**：

1. 用**团结引擎 1.8.2** 建空工程 + asmdef 骨架，按 [08](08-依赖与资源清单.md) 第 7 节装齐依赖；
2. **先花 2 小时**验证 HybridCLR 安装器能否识别 `2022.3.62t4` 这个 `t` 版本（`Installer` + `Generate/All`），这是全项目最大的未知；
3. Addressables 最小闭环（本地组 → 远端 catalog → 增量更新）；
4. HybridCLR 最小热更（`Generate/All` → dll + 元数据入组 → `Assembly.Load` → 入口）；
5. IL2CPP Win64 出包，改一行热更代码，验证不重打包即生效。

只有这一步通过，后面的架构承诺才成立。失败预案见 [04](04-里程碑与实现顺序.md) 第 3 节。
