# 02 架构分层与依赖规则

> 上游：[01-目标与范围](01-目标与范围.md) ｜ 下游：[03-模块清单与优先级](03-模块清单与优先级.md)

## 1. 分层模型

框架分**三层 + 一个横切层**，业务独立成层：

| 层 | 职责 | 典型内容 | 是否进包 |
|---|---|---|---|
| Core | 与玩法无关的基础设施 | 容器、启动、日志、事件、时间、池、异步、存档、配置 | AOT |
| Foundation | 与 Unity 强相关的能力 | 资源、流程、UI、音频、设置、输入、平台 | AOT |
| Gameplay | 可复用的玩法能力 | 角色、相机、交互、任务、关卡 | AOT |
| Game（业务） | 项目逻辑与表现 | 界面、战斗、剧情 | PC 热更 / 主机 AOT |
| Tooling | 编辑器与构建 | 导入规则、检查、出包、CI | 不进 |

分层只解决一件事：**依赖方向永远向下**。向下可以依赖接口，向上只能通过事件或回调。

## 2. 依赖规则

### 2.1 允许 / 禁止矩阵

| 程序集 | 允许引用 | 禁止引用 |
|---|---|---|
| `NowFrameWork.Core` | `UnityEngine.CoreModule`、`System.*` | Foundation、Gameplay、业务、Addressables、UGUI |
| `NowFrameWork.Foundation` | Core、Addressables、UGUI、TextMeshPro、UniTask、Input System | Gameplay、业务 |
| `NowFrameWork.Gameplay` | Core、Foundation、Cinemachine | 业务 |
| `Game.Launcher`（AOT） | Core、Foundation、HybridCLR 运行时 | 业务（热更程序集） |
| `Game.Logic`（热更） | Core、Foundation、Gameplay、同层热更程序集 | — |
| `Game.UI`（热更） | Core、Foundation、`Game.Logic` 的公共接口 | — |
| `Game.Entry.Console` | Core、`Game.Logic`（主机 AOT 双模式，见第 10 节） | — |
| `NowFrameWork.Editor` | 全部运行时程序集 | — |

### 2.2 三条硬规则

1. **AOT 不引用热更**：Launcher 只能通过反射 + AOT 侧接口拿到业务入口。违反会在 HybridCLR 打包阶段直接失败。
2. **下层不引用上层**：Core 不得出现 `using UnityEngine.UI`；Foundation 不得出现 `using Game.Gameplay`。
3. **业务不引用实现类**：业务代码只 `using NowFrameWork.Core;` / `NowFrameWork.Foundation;` 中的接口与数据契约，不直接 `new` 框架内部类。

### 2.3 边界检查自动化

`T01` 提供 `NowFrameWork/Validate Assembly References` 编辑器命令，解析全部 asmdef 的引用列表并与上表比对；越界即报错。该检查接入 CI 的 PR 阶段（见 [06](06-工程规范-测试与验收.md) 第 7 节）。

## 3. 程序集清单

| asmdef | 路径 | 层 | 平台 | 引用 | 构建产物 |
|---|---|---|---|---|---|
| `NowFrameWork.Core` | `Packages/com.now.nowframework/Runtime/Core` | Core | 全平台 | `UnityEngine.CoreModule`、`UniTask` | AOT |
| `NowFrameWork.Foundation` | `Packages/com.now.nowframework/Runtime/Foundation` | Foundation | 全平台 | Core、`Unity.Addressables`、`Unity.ResourceManager`、`UnityEngine.UI`、`Unity.TextMeshPro`、`Unity.InputSystem`、`UniTask` | AOT |
| `NowFrameWork.Gameplay` | `Packages/com.now.nowframework/Runtime/Gameplay` | Gameplay | 全平台 | Core、Foundation、`Unity.Cinemachine` | AOT |
| `NowFrameWork.Editor` | `Packages/com.now.nowframework/Editor` | Tooling | Editor | 以上全部 | 不进包 |
| `NowFrameWork.Tests.EditMode` | `Packages/com.now.nowframework/Tests/EditMode` | 测试 | Editor | Core、Foundation、`nunit.framework` | 不进包 |
| `Game.Launcher` | `Assets/_Project/Launcher` | 启动 | 全平台 | Core、Foundation、HybridCLR 运行时 | AOT |
| `Game.Logic` | `Assets/_Project/HotUpdate/Logic` | 业务 | 全平台 | Core、Foundation、Gameplay | PC 热更 / 主机 AOT |
| `Game.UI` | `Assets/_Project/HotUpdate/UI` | 业务 | 全平台 | Core、Foundation、Game.Logic | PC 热更 / 主机 AOT |
| `Game.Data` | `Assets/_Project/HotUpdate/Data` | 业务 | 全平台 | Core、Foundation | PC 热更 / 主机 AOT |
| `Game.Entry.Console` | `Assets/_Project/Entry.Console` | 业务入口 | PS5 / Xbox Series | Core、Game.Logic、Game.UI | AOT（主机） |

要点：

- 所有 asmdef **关闭 `Auto Referenced`**，引用关系必须显式声明，避免 Assembly-CSharp 意外引用热更程序集。
- 框架内部不再细分更多程序集：3 个运行时 asmdef 已足够，程序集过碎会拖慢编译并放大依赖管理成本。
- `Game.Launcher` 是唯一挂在场景上的 AOT `MonoBehaviour` 入口（Boot 场景），其余全部由代码创建。
- `NowFrameWork.Gameplay` 是**可选取用层**：框架 P0 交付不依赖它，2D 项目只替换本层实现即可，Core / Foundation 一行不改（[ADR-021](07-架构决策记录ADR.md)）。

## 4. 目录结构

```
<Work Root>/
├─ NowFrameWork/                   ★ 游戏工程（本仓库）
│  ├─ Assets/
│  │  ├─ _Project/
│  │  │  ├─ Scenes/               SC_Boot.unity、SC_MainMenu.unity…（Boot 必须进 Build Settings）
│  │  │  ├─ Launcher/             Game.Launcher.asmdef（AOT 唯一入口）
│  │  │  ├─ HotUpdate/            Game.Logic / Game.UI / Game.Data.asmdef（PC 热更）
│  │  │  ├─ Entry.Console/        Game.Entry.Console.asmdef（仅主机平台编译，PC 不参与）
│  │  │  ├─ Settings/             URP/输入/画质等配置资产
│  │  │  ├─ Art/                  项目美术资源（框架不关心）
│  │  │  └─ Resources/            仅放兜底热更 dll 与 AOT 补充元数据 bytes（ADR-020）
│  │  ├─ _ThirdParty/             三方源码型依赖（如有）
│  │  ├─ _Raw/                    原始表格、PSD 等，不进包（.git 大文件走 LFS）
│  │  └─ AddressableAssetsData/   Addressables 组与配置（只由团结 1.8.2 保存）
│  ├─ Packages/
│  │  ├─ manifest.json            只声明依赖；框架包不内嵌（ADR-001）
│  │  └─ packages-lock.json       必须入库
│  ├─ docs/                       本设计文档（仓库根，不放 Assets/ 下）
│  ├─ Tools/                      构建、CI、表格导出脚本
│  ├─ ProjectSettings/
│  └─ README.md
└─ com.now.nowframework/          ★ 框架本体（独立 Git 仓库，UPM 本地包）
   ├─ package.json
   ├─ Runtime/{Core,Foundation,Gameplay}/
   ├─ Editor/
   ├─ Tests/{EditMode,PlayMode}/
   ├─ Samples~/                   示例工程（可导入）
   └─ Documentation~/
```

约定：

- `Assets/_Project` 下的三个下划线目录（`_Project`、`_ThirdParty`、`_Raw`）永远排在最前，避免与 Unity 自动生成目录混排。
- **Boot 场景挂在 Build Settings 的第一位，不进 Addressables**；`Resources/` 只放兜底热更 dll 与 AOT 补充元数据 bytes，其余资源一律 Addressables（ADR-020）。
- 框架包是**独立仓库**，通过 `"com.now.nowframework": "file:../com.now.nowframework"` 引用；游戏工程内不内嵌框架副本，否则"业务工程零复制"与 G1 都不成立（ADR-001）。单工程开发期可以内嵌，但提交前必须外置。
- `docs/` 在仓库根，不要放 `Assets/` 下：放进去会被 Unity 导成 TextAsset，每次改文档都产生 meta 噪音，迁移时还要额外转换。
- 框架包内的代码不得出现任何项目名、项目路径或项目特有的资源名。

## 5. 启动时序

```
SC_Boot.unity
   │
   ├─ 1. Launcher.Awake          Game.Launcher（AOT）创建 ModuleHub
   ├─ 2. IPlatform 初始化         路径、语言、平台能力（C12）
   ├─ 3. 读取内置版本配置          AppVersion / ResourceVersion / HotfixVersion（T02 写入）
   ├─ 4. 核心模块启动             C01 容器 → C03 日志 → C04 事件 → C05 时间 → C07 异步
   ├─ 5. 资源初始化               F01：Addressables.InitializeAsync + Catalog 检查/更新
   ├─ 6. 补丁检查与下载           F02：比对远端清单 → 下载 → 校验 → 落盘（可跳过）
   ├─ 7. 热更加载（PC）           元数据 dll → 按拓扑序 Assembly.Load → 反射业务入口
   │    └─ 主机：跳过，直接走 AOT 入口（Game.Entry.Console）
   ├─ 8. 业务层初始化             C10 配置表 → C11 本地化 → F07 设置 → C09 存档 → F06 音频
   │                              → F08 输入 → F04 UI
   └─ 9. 进入首个流程              F03 → Splash → MainMenu
```

时序约束：

1. **第 4 步之前不允许任何资源加载**——日志与事件必须先就绪，否则失败无从记录。
2. **第 7 步必须在第 8 步之前**——业务类型由热更程序集提供。
3. **第 8 步内部顺序不可交换**：配置表 → 本地化 → 设置（设置依赖本地化取文本）→ 存档 → 音频 → 输入 → UI。
4. 每一步都必须上报归一化进度（`0–1` 映射到 Boot 进度条），不允许黑屏无反馈（ADR-011）。

### 5.1 失败与降级

| 步骤 | 失败处理 | 玩家可见结果 |
|---|---|---|
| 1–2 平台/入口 | 记录错误 → 安全模式 | 内置错误面板 + 日志导出按钮 |
| 3 版本配置缺失 | 用 `0.0.0` 兜底并告警 | 正常启动，日志有 Error |
| 4 核心模块 | 关键模块失败 → 安全模式；非关键失败 → 记录后继续 | 视模块而定 |
| 5 Addressables 初始化 | 重试 3 次（0.5s/1s/2s）→ 仍失败进安全模式 | 错误面板 + 重试按钮 |
| 5 Catalog 更新 | 回退内置 catalog 继续 | 正常启动，提示"资源更新失败" |
| 6 补丁下载 | 跳过补丁，用当前版本启动 | 正常启动，设置页可见版本号 |
| 7 元数据/热更 dll | 回退兜底 dll → 仍失败进安全模式 | 正常启动或错误面板 |
| 8 业务初始化 | 模块级隔离：单模块异常不阻断其余；关键模块失败 → 回退主菜单 | 部分功能不可用 |
| 9 首个流程 | 回退到 MainMenu → 失败则安全模式 | 主菜单或错误面板 |
| 运行期未捕获异常 | 计数 + 上报 + 保留堆栈，不吞异常 | 崩溃或降级 |

原则：**能降级就不退出，能回退就不阻塞**。

## 6. 模块契约

以下为设计草案签名，M1 落地时允许微调，但**语义不得改变**（业务代码按此编写）。

### 6.1 模块与容器（C01）

```csharp
public readonly struct ModuleContext
{
    public ILog Log { get; }
    public IEventBus Events { get; }
    public ITime Time { get; }
    public IPlatform Platform { get; }
    public IAssetService Assets { get; }   // Core 启动阶段为 null，Foundation 阶段注入
}

public interface IAppModule
{
    string Id { get; }                        // 唯一，建议 = 类型名
    IReadOnlyList<string> DependsOn { get; }  // 依赖模块 Id，用于拓扑排序
    void OnInit(in ModuleContext context);    // 只做构造与注册，禁止重 IO
    void OnStart();                           // 全部 OnInit 完成后调用
    void OnShutdown();                        // 逆初始化顺序调用
}

public interface IModuleHub
{
    void Register(IAppModule module);
    void Startup();                                       // 拓扑排序 → 全部 OnInit → 全部 OnStart
    void Shutdown();                                      // 逆序 OnShutdown
    T Get<T>() where T : class;
    bool TryGet<T>(out T module) where T : class;
    void Tick(float deltaTime, float unscaledDeltaTime);   // 由 Launcher 每帧驱动
    void LateTick();
    void FixedTick();
}
```

规则：依赖缺失、循环依赖、重复 Id 一律在 `Startup` 前抛异常并打印完整链路；不允许多个模块各自持有 `static` 单例。

### 6.2 事件总线（C04）

```csharp
public interface IEventBus
{
    IDisposable Subscribe<T>(Action<T> handler, int order = 0) where T : struct;
    void Unsubscribe<T>(Action<T> handler) where T : struct;
    void Publish<T>(in T evt) where T : struct;          // 同步立即派发
    void PublishDeferred<T>(in T evt) where T : struct;  // 帧末统一派发
    void FlushDeferred();
}
```

规则：事件必须是 `struct` 以避免装箱；派发中订阅/退订不得抛 `InvalidOperationException`（内部用快照）；单个 handler 抛异常不得影响其余 handler（记录后继续）。

```csharp
public interface ITime

```

### 6.4 资源（F01）

```csharp
[Serializable]
public struct AssetRef<T> where T : UnityEngine.Object
{
    [SerializeField] private string m_Address;
    [SerializeField] private string m_Package;   // 空 = 默认包
    public bool IsValid { get; }
    public string Address { get; }
}

public readonly struct AssetHandle<T> : IAssetHandle, IDisposable where T : UnityEngine.Object
{
    public T Asset { get; }
    public bool IsValid { get; }
    public void Dispose();                       // 等价于 IAssetService.Release(this)
}

public interface IAssetService
{
    AssetHandle<T> Load<T>(in AssetRef<T> reference) where T : UnityEngine.Object;
    UniTask<AssetHandle<T>> LoadAsync<T>(in AssetRef<T> reference, CancellationToken ct = default)
        where T : UnityEngine.Object;
    UniTask PreloadAsync(IReadOnlyList<IAssetRef> refs, IProgress<float> progress = null,
        CancellationToken ct = default);
    void Release(IAssetHandle handle);
    int GetRefCount(string address);
    IReadOnlyList<AssetLeakInfo> Snapshot();     // 未释放句柄快照（Editor/诊断包）
}
```

规则：

1. `AssetHandle<T>` 的语义是**唯一所有权，不得复制**：不要存进字段/集合后再取出、不要按值传参。M1 落地时二选一消除误用——改成 `sealed class`，或保留 struct 但加 `_released` 标记，并在 Editor 下对"同一句柄 Dispose 两次"直接抛异常（只警告会把计数减成负数）。
2. 引用计数归零才真正 `Addressables.Release`；`Dispose()` 是唯一释放入口。
3. 不允许把句柄存进静态字段或跨流程持有；跨流程要在 `OnEnterAsync` 申请、`OnExitAsync` 释放。

### 6.5 流程（F03）

```csharp
public interface IFlowState
{
    UniTask OnEnterAsync(FlowContext context, CancellationToken ct);
    UniTask OnExitAsync(CancellationToken ct);
    void OnTick(float deltaTime);
}

public interface IFlowService
{
    IFlowState Current { get; }
    UniTask ChangeAsync<TState>(object payload = null, CancellationToken ct = default)
        where TState : IFlowState;
    void Tick(float deltaTime);
}
```

规则：`ChangeAsync` 必须串行（后一次等待前一次完成或取消前一次），不允许并发的流程切换。

流程实例的来源也要定死：`TState` 不能靠 `Activator.CreateInstance` 反射构造（IL2CPP 裁剪下不可靠），由 `IFlowService` 在初始化时注册的工厂提供，缺注册启动即报错。

### 6.6 UI（F04）

```csharp
public enum UILayer { Background, Normal, Popup, Top, Toast, Loading }

public abstract class UIView : MonoBehaviour
{
    public UILayer Layer { get; }
    protected virtual void OnCreate() { }
    protected virtual UniTask OnShowAsync(object args, CancellationToken ct) => UniTask.CompletedTask;
    protected virtual void OnHide() { }
    protected virtual void OnUpdate() { }
    protected virtual bool OnBack() => false;   // 返回键是否被消费
}

public interface IUIService
{
    UniTask<T> OpenAsync<T>(UILayer layer = UILayer.Normal, object args = null,
        CancellationToken ct = default) where T : UIView;
    UniTask<T> PushAsync<T>(object args = null, CancellationToken ct = default) where T : UIView;
    UniTask CloseAsync(UIView view);
    UniTask PopAsync();
    bool IsOpen<T>() where T : UIView;
    void CloseAll(UILayer layer);
}
```

规则：业务代码不得直接 `Instantiate` 界面 Prefab；界面的创建、缓存、层级与返回键全部由 `IUIService` 托管。

界面地址约定（M3 落地时固化，避免"从类型到 Prefab"的隐式反射）：

- `UIView` 子类用 `[UIViewAddress("UI/MainMenu")]` 标注地址，地址规则见 [05 §1.6](05-技术方案-Addressables与HybridCLR.md)；
- 构建期由 T01 扫描生成静态注册表，运行期 `OpenAsync<T>()` 只查表，**不做反射扫描**（IL2CPP 裁剪后按字符串找类型不可靠）；
- 没标注地址的 `UIView` 在构建期直接报错，不要留到运行期才炸。

```csharp
public interface ILocalizationService
```

## 7. 典型数据流

### 7.1 一次资源加载

```
业务 ──LoadAsync(AssetRef)──▶ IAssetService ──▶ 加载队列（并发上限 6）
                                                   │
                                                   ├─ 命中缓存：refCount++，立即返回
                                                   └─ 未命中：Addressables.LoadAssetAsync
                                                                │
                                    句柄返回业务 ◀──────────────┘
业务 ──Dispose()──▶ refCount-- ──▶ 归零 ──▶ Addressables.Release
```

### 7.2 一次界面打开

```
业务 ──OpenAsync<T>()──▶ IUIService
                          ├─ 查缓存池 → 命中则复用
                          ├─ 未命中 → IAssetService 加载 Prefab → Instantiate 到对应层级
                          ├─ 设置 SortingOrder、遮罩、焦点
                          └─ OnShowAsync(args) ──▶ 业务绑定数据
关闭 ──▶ OnHide（不销毁）──▶ 回缓存池（超上限才 Destroy）
```

### 7.3 一次流程切换

```
IFlowService.ChangeAsync<BattleFlow>
  ├─ 串行锁
  ├─ 当前流程 OnExitAsync（保存状态、释放场景资源）
  ├─ 打开 Loading 界面（UILayer.Loading）
  ├─ Addressables 卸载旧场景 → 加载新场景（Additive）
  ├─ BattleFlow.OnEnterAsync（初始化关卡、实体）
  ├─ 关闭 Loading（进度 1.0 后至少停留 0.2s，避免闪烁）
  └─ 释放串行锁
```

## 8. 生命周期与关闭

- 启动：`ModuleHub.Startup()` 一次性完成拓扑排序，之后不允许再注册模块（Editor 允许，运行时禁止）。
- 每帧：`Launcher.Update → ModuleHub.Tick → IUpdatable 模块`，顺序与初始化顺序一致。
- 关闭：`Shutdown()` 逆序执行，每个模块 5 秒超时；超时记录并继续，不阻塞退出。
- 应用退出（`OnApplicationQuit` / 主机 `OnApplicationPause`）必须走同一 `Shutdown` 路径，保证存档落盘。
- Editor 域重载：`ModuleHub` 只允许持有一次性静态引用，并在 `[InitializeOnLoad]` 中重置，避免域重载后残留。

## 9. 错误处理约定

| 场景 | 约定 |
|---|---|
| 参数非法 | 抛 `ArgumentException`，不返回默认值 |
| 资源缺失 | 抛 `AssetLoadException`，由调用方决定回退或提示 |
| 网络/下载失败 | 不抛到业务，返回失败结果 + 重试接口 |
| 模块初始化异常 | 容器捕获 → 标记模块失败 → 汇总报告 |
| 未捕获异常 | `Application.logMessageReceived` 计数与上报，**不吞异常** |
| 可预期的业务失败 | 用返回值或 `TryXxx`，不用异常控制流程 |

## 10. 主机双模式（条件项）

> 仅在主机立项时启用：团结引擎不提供 PS5 / Xbox 构建目标，立项即**整体迁移**到 Unity 2022.3.67f2（GUID/场景格式转换 + 重烘场景 + 重打 AB，预估 5–8 人日，ADR-017）。PC-only 阶段该入口程序集不编译、构建变体不切换，零成本保留设计。

同一份业务代码，两种编译方式：

```
PC（SupportsHotUpdate = true）
  HotUpdateAssemblies = [Game.Logic, Game.UI, Game.Data]
  Launcher ──反射──▶ IGameEntry（实现类在热更层）
  业务 dll 由 Addressables 分发，可热更

主机（SupportsHotUpdate = false）
  HotUpdateAssemblies = []          ← 构建变体切换
  Game.Entry.Console（AOT，includePlatforms = 主机）──直接引用──▶ Game.Logic
  业务代码随包编译，补丁走整包审核
```

实现要点：

1. `Game.Entry.Console` 的 asmdef `includePlatforms` 只勾选主机平台，PC 构建时它不参与编译，因此 PC 包内不存在"业务 AOT 程序集"。
2. 主机入口与 PC 入口实现同一个 AOT 接口 `IGameEntry`（定义在 `NowFrameWork.Core`），业务层不感知差异。
3. 构建脚本按 `BuildContext` 切换 `HotUpdateAssemblies` 列表，不允许手工改配置。

## 11. 如何新增一个模块

1. 定编号（C/F/G/T + 序号），补 [03](03-模块清单与优先级.md) 附表；
2. 定优先级与依赖，确认依赖方向合法（第 2 节）；
3. 接口定义在所属层的 `Abstractions` 子目录，实现放同层内部目录；
4. 实现 `IAppModule`，在 Launcher 的启动序列中显式注册（不允许反射扫描自动注册，启动顺序必须可读）；
5. 补 EditMode 测试与一次 [06](06-工程规范-测试与验收.md) 第 8 节的 DoD 勾选；
6. 若涉及跨层决策，补一条 ADR。
