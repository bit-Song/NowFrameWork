### 3.2 需要通过 git 安装

| 包 | git URL | 锁定方式 | 说明 |

| UniTask | `https://github.com/Cysharp/UniTask.git?path=src/UniTask/Assets/Plugins/UniTask` | 末尾加 `#a77a1b4a89824fb6df293099de3060daf2a432c1`（= 2.5.11） | 包名 `com.cysharp.unitask`；锁 commit，避免上游变更；GitHub 在国内不可靠，建议镜像到内网 |

### 3.3 manifest.json 模板

`Packages/manifest.json` 的 `dependencies` 片段（版本按 M0 实测微调）：

```json
{
  "dependencies": {
    "com.unity.addressables": "1.22.4-t1",
    "com.unity.inputsystem": "1.14.2",
    "com.unity.textmeshpro": "3.0.9",
    "com.unity.ugui": "1.0.0",
    "com.unity.test-framework": "1.1.33",
    "com.unity.testtools.codecoverage": "1.2.6",
    "com.cysharp.unitask": "https://github.com/Cysharp/UniTask.git?path=src/UniTask/Assets/Plugins/UniTask#<commit>",
    "com.code-philosophy.hybridclr": "https://github.com/focus-creative-games/hybridclr_unity.git#<tag>"
  }
}
```

安装后必须提交 `Packages/packages-lock.json`，它是"这台机器装的是哪些版本"的唯一凭据，也是换机/CI 可复现的前提。

## 7. M0 第一天的安装顺序

1. `git --version` 确认可用（HybridCLR / UniTask 都要 git）；
2. 用团结 1.8.2 新建工程，`Packages/manifest.json` 按 3.3 改好；
3. Package Manager 里确认 Addressables 锁在 **1.22.4-t1**，不要点"升级"；
4. 导入 TMP Essential Resources；
5. 执行 `HybridCLR/Installer...` → `HybridCLR/Generate/All`；
6. 建一个空场景 + 一个 UGUI 文本，出 Win64 IL2CPP 包；
7. 提交 `manifest.json` + `packages-lock.json` + `ProjectSettings/ProjectVersion.txt`（Unity 侧验证已随 ADR-017 v0.3 取消）。

## 8. 版本漂移、升级策略与处理

> 决策依据：[ADR-018](07-架构决策记录ADR.md)（Addressables 版本策略）与 [ADR-019](07-架构决策记录ADR.md)（资源方案选型）。

### 8.1 三条硬规则

1. **锁 1.22.4-t1**：`manifest.json` 显式 pin，任何人不点"升级"；`packages-lock.json` 入库。它不随编辑器安装，换机后按 manifest 重新解析即可。
2. **只有一个环境写数据**：`AddressableAssetsData` 只由团结 1.8.2 保存；v0.3 起没有第二个环境，迁移时按新工程重建。
3. **升级即大版本发布**：只在 M2 前或 M4 前窗口升级；升级后重建 Addressables、重出全量包、作废旧 content state，禁止跨版本出内容补丁。

### 8.2 升级 checklist（触发 ADR-018 时执行）

1. 备份 `AddressableAssetsData`、`addressables_content_state.bin` 与版本清单；
2. 新建分支（官方要求：内容更新/升级前先分支，避免分组被工具重排后污染主线）；
3. 升级包版本 → 重开工程 → 确认 `AddressableAssetSettings` 无报错；
4. 重建分组与 Profile，重跑 Analyze（冗余、重复依赖）；
5. 全量构建 Addressables，生成**新的** `addressables_content_state.bin`（旧的作废）；
6. 出 Player 包，`ResourceVersion` 自增；
7. 基于新 state 出一次补丁，验证补丁链路仍可用；
8. 用旧客户端升级到新包验证（重点看下载量是否变为全量）；
9. 更新版本矩阵与 ADR，跑一次 CI 冒烟。

### 8.3 现象与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| Addressables 面板报错或数据异常 | 包被换成 Unity 官方 1.22.3 / 升到 2.x，序列化了不同格式 | 改回 1.22.4-t1，删 `Library` 重解析；必要时重建 `AddressableAssetsData` |
| 打开工程时 `manifest.json` 解析失败 | 引入了 `file:../.codely-cli/...` 这类本机路径依赖 | 移除该条依赖后再解析 |
| 首次打开工程很慢 | `Library` 重建 | 接受（首次几分钟） |
| 热更生成/打包报找不到 il2cpp 或 `LocalIl2CppData-*` | `Library` 被删/被清理，安装数据在 `Library/HybridCLR/` 里一起没了 | 重跑 `HybridCLR/Installer...`（约 0.8 GB，从 gitee 拉 `v2022.3.x-tuanjie-9.1.0`） |
| HybridCLR 安装后编译报错 | 团结版本与 HybridCLR 不匹配 | 回退到上一个可用 tag；记录进版本矩阵 |
