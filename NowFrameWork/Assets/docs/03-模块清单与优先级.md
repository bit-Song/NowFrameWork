# 03 模块清单与优先级

> 上游：[02-架构分层与依赖规则](02-架构分层与依赖规则.md) ｜ 下游：[04-里程碑与实现顺序](04-里程碑与实现顺序.md)

## 1. 优先级定义与统计

| 等级 | 含义 | 判定标准 |
|---|---|---|
| **P0** | 骨架必备 | 没有它，M0–M4 的退出标准无法达成；缺失会导致其他模块无法落地 |
| **P1** | 通用能力 | 中大型单机项目普遍需要；可延后，但接入成本随项目推进上升 |
| **P2** | 按项目取用 | 只有特定类型项目需要（RPG/动作/Mod 社区）；默认不实现 |

| 层 | 模块数 | P0 | P1 | P2 |
|---|---|---|---|---|
| Core | 12 | 10 | 2 | 0 |
| Foundation | 12 | 3 | 7 | 2 |
| Gameplay | 9 | 0 | 3 | 6 |
| Tooling | 6 | 5 | 1 | 0 |
| 合计 | 39 | 18 | 13 | 8 |

里程碑列说明：`M0` 预研、`M1` 内核、`M2` 资源流程配置、`M3` UI 表现存档、`M4` 热更出包、`M5` Gameplay、`M6` 工程化。

> **交付边界（v0.3）**：18 个 P0 全部落在 Core / Foundation / Tooling，框架本体不含任何渲染或物理实现。Gameplay 的 9 个模块全是 P1/P2，按 [ADR-021](07-架构决策记录ADR.md) 只交付**接口 + `Samples~` 参考实现**，不进入框架 P0 验收；2D 项目按同一套接口自行实现，框架不提供 2D/3D 双套实现。

## 7. 裁剪指南

| 项目形态 | 建议集合 | 说明 |
|---|---|---|
| 原型 / 小体量（< 3 人月） | P0 + G01 + G04 + G05 | 不做热更、设置、云端；UI 用 P0 |
| 中大型单机（默认） | P0 + P1 | 本框架的目标形态 |
| 全量 | 39 个 | 含 Mod、回放、统计上报 |

裁剪实现方式：

1. **不注册即不运行**：P1/P2 模块默认在启动序列中不出现，代码存在但零运行时开销。
2. **不引用即不进泛型实例**：业务不引用即不会触发静态构造；框架层禁止有副作用的静态构造函数。
3. **IL2CPP 负责裁剪未用代码**；因此 P1/P2 模块必须能被独立编译，不得与 P0 代码强耦合。
4. Gameplay 若整体不需要，可在 UPM 包中通过 `version define` 关闭，减少编译时间（可选优化，M6 再做）。
